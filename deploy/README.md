# RouteTimer deployment

1. Set `ROUTETIMER_DB_PASSWORD` and `KEYCLOAK_AUTHORITY` (for example `https://auth.example.com/realms/routetimer`) in the deployment environment. `Auth__Mode` is set to `Keycloak` by the Compose file and must not be removed: the application refuses to start without an explicit authentication mode. Neither is a build argument any more — the image is built once and configured at run time.
2. Generate the Garmin token-encryption key with `openssl rand -base64 32` and store the output in the deployment secret named `ROUTETIMER_GARMIN_TOKEN_KEY`. Do not commit the value, put it in Compose YAML, paste it into an issue, or include it in a screenshot or log bundle. RouteTimer passes this key only to the API; the private Garmin adapter receives neither this key nor database credentials. The fixed key in `appsettings.Development.json` exists only so the app starts on a developer machine — it is published in this repository and must never be used in a deployment.
3. Treat the Garmin key as persistent data. Rotating or losing it makes the existing encrypted Garmin token bundle unreadable and requires the rider to reconnect Garmin. For planned rotation, disconnect Garmin first, replace the deployment secret, restart RouteTimer, and reconnect. Imported FIT evidence, parsed activities, and model history remain after disconnect.
4. Replace `ROUTETIMER_HOSTNAME` in `keycloak/routetimer-realm.json` with the deployment's real hostname, then import the file into the existing Keycloak instance. Assign the realm `rider` role to the rider account. This Compose project does not read `ROUTETIMER_HOSTNAME` itself — it is only a placeholder in the realm file and in `caddy/routetimer.caddy`, substituted by hand here and set in the shared ingress's own environment for step 6.
5. Start with `docker compose up -d --build`. The app, adapter, and database publish no host ports; only the app joins `mcp-public`. RouteTimer reaches the adapter at `http://routetimer-garmin-adapter:8081` on the internal `routetimer-private` network and waits for its health check before starting. Only the adapter also joins the non-internal `garmin-egress` bridge so it can initiate Garmin HTTPS requests; RouteTimer and PostgreSQL do not join that egress network.
6. Copy `caddy/routetimer.caddy` into the shared ingress drop-in directory, validate Caddy, then reload it. Do not add a Caddy route for the Garmin adapter.
7. Run the opt-in real-account procedure in [`docs/garmin-smoke-test.md`](../docs/garmin-smoke-test.md) before releasing this unofficial integration or after upgrading its pinned Garmin dependency. It must remain outside CI.
8. Treat `garmin-adapter/requirements.lock` and the Python base-image digest as reviewed release inputs. After intentionally changing a dependency pin in `pyproject.toml`, install `pip-tools==7.5.1` in the adapter's local virtual environment and regenerate the lock with `.venv/bin/pip-compile pyproject.toml --output-file requirements.lock --generate-hashes --resolver backtracking --strip-extras --all-build-deps --allow-unsafe`; review the resolved versions and hashes, then rerun Python checks and the adapter Docker build. Refresh the `python:3.12-slim` digest deliberately when adopting an upstream base update, and rebuild before deployment.
