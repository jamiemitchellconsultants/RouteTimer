# RouteTimer deployment

1. Set `ROUTETIMER_DB_PASSWORD`, `KEYCLOAK_AUTHORITY` (for example `https://auth.example.com/realms/routetimer`), and `ROUTETIMER_HOSTNAME` in the deployment environment. The public authority and hostname are build arguments because the WASM OIDC configuration is a static asset.
2. Generate the Garmin token-encryption key with `openssl rand -base64 32` and store the output in the deployment secret named `ROUTETIMER_GARMIN_TOKEN_KEY`. Do not commit the value, put it in Compose YAML, paste it into an issue, or include it in a screenshot or log bundle. RouteTimer passes this key only to the API; the private Garmin adapter receives neither this key nor database credentials.
3. Treat the Garmin key as persistent data. Rotating or losing it makes the existing encrypted Garmin token bundle unreadable and requires the rider to reconnect Garmin. For planned rotation, disconnect Garmin first, replace the deployment secret, restart RouteTimer, and reconnect. Imported FIT evidence, parsed activities, and model history remain after disconnect.
4. Import `keycloak/routetimer-realm.json` into the existing Keycloak instance, replacing `ROUTETIMER_HOSTNAME` first. Assign the realm `rider` role to the rider account.
5. Start with `docker compose up -d --build`. The app, adapter, and database publish no host ports; only the app joins `mcp-public`. RouteTimer reaches the adapter at `http://routetimer-garmin-adapter:8081` on the internal `routetimer-private` network and waits for its health check before starting.
6. Copy `caddy/routetimer.caddy` into the shared ingress drop-in directory, validate Caddy, then reload it. Do not add a Caddy route for the Garmin adapter.
7. Run the opt-in real-account procedure in [`docs/garmin-smoke-test.md`](../docs/garmin-smoke-test.md) before releasing this unofficial integration or after upgrading its pinned Garmin dependency. It must remain outside CI.
